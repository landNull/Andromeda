# Andromeda — install the host, then run the CLI

system:
  os: Devuan (sysvinit) on the devel host; any Debian-family or similar on a laptop / VPS
  hostname: Andromeda
  cpu: (your host)
  ram: 32GB
  storage: 2x1TB SSD RAID 1
  stack: Apache + PHP + MariaDB + Bee + crdir
  control: /srv/andromeda
  sites:   /srv/platforms
  no PHP panel  (this is the Aegir / BOA replacement)

--------------------------------------------------------------------
0. Words before any command
--------------------------------------------------------------------

  platform   one Backdrop codebase
             /srv/platforms/ecom
             shared core, modules, themes

  product    one website inside that codebase
             thq and kl both live in ecom
             each has its own DB, files, config

  environment
             devel  = devel host, or a laptop with --localhost
             test   = VPS checkout /srv/platforms/mysite-test
             live   = VPS checkout /srv/platforms/mysite-live
             Never run all three out of one working copy.

  deploy     system account. Owns Git trees and runs Bee.
             HOME /srv/andromeda/home, shell nologin, locked password.
             sudo -u deploy bee|git|crdir. Not a human login.
  git        system account that *runs* the forge (STEP 60), same method
             as deploy: nologin, locked, HOME /var/lib/gitea. Not /home/git.
             git@ in clone URLs is SSH_USER; sshd never gives this user a shell.
  www-admin  file group on every tree. Not a login.
             Grant: usermod -aG www-admin,andromeda,deploy NAME
             The installer adds the invoking login to those three
             groups only. It never adds group sudo.
  operator   whoever ran the installer (or -H NAME). Must already exist.
             After usermod: exec su - $USER
             (exec bash / exec zsh do NOT refresh groups)
  www-data   Apache / PHP daemon user; also in group www-admin
  andromeda   group for secrets + operator (NOT www-data)

  ownership
             files/, files_private/, config/*/active
               www-data:www-admin + setgid + default ACL
             code, staging, /srv/andromeda
               deploy:www-admin + default ACL
             secrets
               deploy:andromeda 0640 + .cnf
               Apache cannot read this directory

  andromeda-priv
             /usr/local/sbin/andromeda-priv
             the only NOPASSWD root helper
             paths only under /srv/platforms and /srv/andromeda
             DB names must start with bd_

  Bee        Backdrop CLI (not Drush)
             always: bee --root=/srv/platforms/PLATFORM/web --site=PRODUCT …

  d7-migrate BOA / Drupal 7 -> Backdrop on knarr
             prep on the VPS, assess + convert + attach on knarr
             never runs bee install (that would wipe the D7 schema)
             man-style help: d7-migrate help

  crdir      mkdir + chown + 0770
             site-add uses -s -o www-data -g www-admin on PHP trees

Do not type "sudo andromeda", "sudo andromeda-menu", or "sudo andromeda-tui"
(exit 2). The wrapper calls sudo -n /usr/local/sbin/andromeda-priv only.

Always run a mutating command once with -n first.
-n prints each action with a leading + and changes nothing.

1. What you copy onto the machine
--------------------------------------------------------------------

Clone the tools repo (not a Backdrop platform). Layout:

  andromeda-install.sh     run from the repo root
  bin/                    andromeda, andromeda-priv, andromeda-menu, crdir, newfeature
  lib/                    modules sourced by bin/andromeda
  man/                    andromeda.1 crdir.1
  docs/tutorial.txt
  conf/andromeda-settings.json
  tui/                    Bubble Tea source (optional; no binary in git)

On the box:

  chmod +x andromeda-install.sh bin/*
  ./andromeda-install.sh -n -m devel

Help after install:

  andromeda -h
  andromeda --help
  man andromeda          # after the installer has run
  man ./andromeda.1      # from this folder, before install
  man crdir

1b. Put Andromeda itself in Gitea (localhost first)
--------------------------------------------------------------------

Andromeda is a repo of TOOLS, not a Backdrop platform.
Do not run "andromeda platform-add andromeda".
Do not put /srv/platforms or /srv/andromeda/state/secrets in this repo.

What belongs in git@git.example:org/andromeda.git

  andromeda-install.sh
  andromeda
  andromeda.1
  andromeda-lib/*.sh
  andromeda-settings.json
  andromeda-tutorial.txt
  crdir  crdir.1
  newfeature

What does NOT belong

  /srv/andromeda/state/secrets/
  /srv/andromeda/state/tasks.log
  /srv/andromeda/backups/
  /srv/platforms/
  settings.local.php from any site

On the Gitea web UI (same instance as ecom):

  New repository
    Owner:     ORG          (same org as ecom / torg)
    Name:      andromeda
    Visibility: private
    Init:      empty (no README from the UI if you already have files)

On the laptop, after a --localhost install (or from this artifacts folder
before install):

  cd /path/to/the/folder/that/holds/andromeda-install.sh
  printf '%s\n' \
    '/srv/' \
    'state/secrets/' \
    'state/tasks.log' \
    'backups/' \
    '*.sql' \
    '.DS_Store' > .gitignore

  git init
  git checkout -B devel
  git add andromeda-install.sh andromeda andromeda.1 andromeda-lib \
    andromeda-settings.json andromeda-tutorial.txt \
    crdir crdir.1 newfeature .gitignore
  git status
  git commit -m "andromeda CLI + installer + lib"

  # first time only — name the remote
  git remote add origin git@git.example:org/andromeda.git

  # if you already added origin and need to point it again:
  # git remote set-url origin git@git.example:org/andromeda.git

  git remote -v
  # origin  git@git.example:org/andromeda.git (fetch)
  # origin  git@git.example:org/andromeda.git (push)

  ssh -T git@git.example
  # must succeed as YOUR Gitea user (not deploy)

  # first push of branch devel (sets upstream)
  git push -u origin devel

  # every later commit from this laptop
  git add -u
  git commit -m "describe the change"
  git push
  # same as: git push origin devel

If Gitea created a README and the first push is rejected
("updates were rejected because the remote contains work"):

  git fetch origin
  git pull --rebase origin devel
  git push -u origin devel

Do not git push --force on this repo unless you are sure
nothing else has commits you need.

If SSH works but push asks for a password, you are hitting
HTTPS by mistake. The remote MUST start with git@ not https://

  git remote set-url origin git@git.example:org/andromeda.git
  git push -u origin devel

On the devel host or the VPS you clone the tools, then run the installer
from that clone so ship_tools sees andromeda-lib next to the script:

  sudo -u deploy -H git clone \
    -b devel \
    git@git.example:org/andromeda.git \
    /home/deploy/andromeda
  cd /home/deploy/andromeda
  ./andromeda-install.sh -n -m devel     # devel host
  ./andromeda-install.sh -n --localhost  # another laptop

Updates later:

  cd /home/deploy/andromeda
  git pull --ff-only
  ./andromeda-install.sh -n -m devel
  ./andromeda-install.sh -m devel

That re-ships /usr/local/bin/andromeda and /usr/local/lib/andromeda.
It does not touch /srv/platforms.

--------------------------------------------------------------------
2. Install the host  (andromeda-install.sh)
--------------------------------------------------------------------

Pick ONE profile. Preview, then run for real.

2a. Laptop / local dev only  (127.0.0.1)

  ./andromeda-install.sh -n --localhost
  ./andromeda-install.sh --localhost

  Same flag: -lh

  Does:
    deploy + www-admin, Apache, PHP, MariaDB on 127.0.0.1
    Bee, crdir, newfeature, andromeda
    dnsmasq  address=/devel/127.0.0.1
    Listen 127.0.0.1:80

  Skips:
    CSF, WireGuard policy, certbot

2b. devel host  (devel, LAN 192.168.1.120 + WireGuard 10.8.0.1)

  ./andromeda-install.sh -n -m devel
  ./andromeda-install.sh -m devel

  Optional firewall (SSH only via WG 10.8.0.0/24 and LAN 192.168.1.0/24):

  ./andromeda-install.sh -n -F -m devel
  ./andromeda-install.sh -F -m devel

  First CSF pass sets TESTING=1 so a lockout undoes itself.
  After WG SSH still works:

    sudo sed -i 's/^TESTING = .*/TESTING = "0"/' /etc/csf/csf.conf
    sudo csf -r

  dnsmasq on the devel host: address=/devel/192.168.1.120

2c. VPS test

  ./andromeda-install.sh -n -m test
  ./andromeda-install.sh -m test

  No dnsmasq (public DNS / Cloudflare).
  certbot is offered.
  Optional: add -F for CSF. Public inbound is 80+443 and UDP 51820.
  SSH is still not world-open.
  test/live also write /etc/sysctl.d/60-andromeda.conf (BBR if the
  kernel has it; ip_forward=1 for WireGuard), Apache ServerTokens Prod,
  and nofile 65535 for www-data. Rose weekly snapshots are not a CMS
  backup — keep backup-all. Do not open MariaDB 3306 on the public NIC.

2d. VPS live

  ./andromeda-install.sh -n -m live
  ./andromeda-install.sh -F -m live

What every profile does
  creates system account deploy (HOME /srv/andromeda/home, nologin) and group www-admin
  no user named www-admin unless you pass -a NAME (NAME != www-admin)
  puts invoking login in www-admin,andromeda,deploy,adm — never group sudo
  www-data in www-admin
  /srv/andromeda + /srv/platforms 2770 deploy:www-admin + default ACL
  secrets dir 0750 deploy:andromeda; deploy HOME 0700 deploy:deploy (no ACL inherit)
  /etc/andromeda.conf; ~/.andromeda.conf for deploy and the invoking login
  PHP drop-in + optional one php-fpm pool as www-data + mpm_event
  PHP split: 30-andromeda.ini all SAPIs; 35-andromeda-harden.ini FPM/apache2
    (disable_functions; live/test opcache.validate_timestamps=0)
    35-andromeda-cli.ini — no disable_functions so Bee can exec
  PHP extras: intl bcmath imagick apcu
  apache2-utils (ab), mariadb-backup, jq, pv, moreutils, age
  logwatch, goaccess, etckeeper (/etc git), smartmontools, irqbalance, haveged
  unattended-upgrades (security pocket, Automatic-Reboot false)
  needrestart, msmtp-mta (put /etc/msmtprc before NOTIFY= works)
  MariaDB bind 127.0.0.1; root stays unix_socket (do not SET PASSWORD)
    STEP 40 also: load auth_socket, drop anonymous + remote root + test DB
  git safe.directory /srv/platforms for deploy
  sudoers: deploy + %www-admin get NOPASSWD andromeda-priv / bee+git+crdir as deploy
             (no usermod -aG sudo; no per-user sudoers line)
  ships andromeda, andromeda-priv, andromeda-menu, andromeda-tui if built

After any profile

  exec su - "$USER"
  id    # must list www-admin and andromeda
  # deploy forge key: /srv/andromeda/home/.ssh  (not /home/deploy)

The installer does not set passwords and does not invent keys.

--------------------------------------------------------------------
2e. Gitea (optional STEP 60)
--------------------------------------------------------------------

The last install phase asks whether to put a Git forge on THIS host.
Every question prints a one-line "Needed:" description and "(? help)".
Type ? or help for a pager with examples aimed at a new sysadmin. q
closes the pager and returns to the prompt. Enter keeps the default
in [brackets].

Install Gitea on this host?  (Y/n)
  Y on devel / --localhost if you do not already have a forge.
  n on test/live (those hosts clone FROM the forge).
  n if the forge is GitHub (example) or Gitea on another machine.

It will NOT:
  download HTML from https://gitea.com (binary comes from dl.gitea.com,
  sha256 checked, GitHub releases as fallback)
  rewrite an existing /etc/gitea/app.ini
  fail the rest of Andromeda if you skip it

It WILL, if you say Y and app.ini is absent:
  create system user git (nologin, locked, HOME /var/lib/gitea — like deploy)
  no /home/git, no login shell; git@ in URLs is SSH_USER (Gitea SSH on 2222)
  install /usr/local/bin/gitea
  write app.ini (INSTALL_LOCK=true, default branch devel,
    registration closed, Gitea SSH on 2222)
  sysvinit script (systemd/openrc when that is init)
  optional Apache vhost andromeda-gitea (http://HOSTNAME/ → :3000)
  a Gitea admin user
  ANDROMEDA_GIT_TEMPLATE=git@HOST:OWNER/%s.git in /etc/andromeda.conf
  SSH config Host alias (gitforge, Port 2222) so deploy can git ls-remote

Non-interactive (cron / no /dev/tty): skipped unless GITEA_INSTALL=Y.
Theia, sudo, and piped stdin still prompt via /dev/tty when a keyboard
is attached. Optional env: GITEA_DOMAIN GITEA_OWNER GITEA_SSH_HOST GITEA_ADMIN
GITEA_ADMIN_EMAIL GITEA_ADMIN_PASS GITEA_DB=sqlite3|mysql
GITEA_PROXY=Y|n GITEA_SSH=gitea GITEA_VERSION=1.27.3
GITEA_SSH_PORT=2222 GITEA_HTTP_PORT=3000

After a yes:

  browse ROOT_URL, sign in as the admin you named
  create the organization you put in the owner/org prompt
  add deploy's printed public key as a deploy key on that org
  sudo -u deploy git ls-remote git@gitforge:acme/myapp.git

Re-run of install-andromeda.sh is safe: existing Gitea + app.ini
are left alone; only a missing ANDROMEDA_GIT_TEMPLATE is prompted.

--------------------------------------------------------------------
3. Prove the box is ready
--------------------------------------------------------------------

  andromeda doctor
  andromeda env
  andromeda list

doctor must print READY before you add platforms.
env shows the role (devel/test/live) loaded from conf.
list is empty until you add a platform.

If doctor fails:
  bee / crdir not on PATH  → re-run the installer from the folder
                             that contains those files
  user www-admin missing   → expected; www-admin is a group, not a login
  user deploy missing      → installer did not finish; run it again
  /srv/platforms missing   → same
  missing group www-admin  → sudo usermod -aG www-admin,andromeda "$USER"
                             then: exec su - "$USER"
  ACL mask effective r--   → sudo -n /usr/local/sbin/andromeda-priv setacl /srv/platforms

Front-ends (same verbs, no extra privileges):

  andromeda-menu     # gum, else whiptail, else dialog
  andromeda-tui      # Bubble Tea; ANDROMEDA_BIN overrides the CLI path

  sudo apt-get install -y gum     # nicer menu; optional

--------------------------------------------------------------------
4. andromeda commands
--------------------------------------------------------------------

Global flag (before the command name):

  -n     dry run
  -h     help  (also: --help   or   andromeda help)

4.1  andromeda doctor
     Check users, dirs, bee, crdir, Apache, PHP, MariaDB.
     CSF and WireGuard are notes, not failures.

       andromeda doctor

4.2  andromeda env
     Print ANDROMEDA_ROLE, paths, Bee binary, Apache reload command.

       andromeda env

4.3  andromeda list
     Walk /srv/platforms. Print branch + product folders
     that already have settings.php.

       andromeda list

4.4  andromeda platform-add NAME [--git URL] [--branch BRANCH]

     Creates /srv/platforms/NAME.
     Existing directory is left alone.

     Fresh Backdrop (no Git yet):

       andromeda -n platform-add scratch
       andromeda platform-add scratch

     Clone ecom from Gitea onto the devel host:

       andromeda -n platform-add mysite \
         --git git@git.example:org/mysite.git \
         --branch devel
       andromeda platform-add mysite \
         --git git@git.example:org/mysite.git \
         --branch devel

     Default --branch is ANDROMEDA_ROLE from conf (devel on the devel host).

4.5  andromeda site-add PLATFORM PRODUCT [--host HOST] [--name TITLE] [--pass PASS]

     Adds one product inside an existing platform.

     Does, in order:
       crdir -s  files/PRODUCT files_private/PRODUCT config/PRODUCT/active
       crdir     config/PRODUCT/staging
       settings.php path overrides
       sites.php map  $sites['HOST'] = 'PRODUCT'
       settings.local.php  (not overwritten if present)
       CREATE DATABASE + USER  bd_PRODUCT_ROLE @ localhost
       bee --site=PRODUCT install --auto
       Apache vhost PLATFORM-ROLE.conf + reload

     Default --host is PRODUCT.ROLE  e.g. www.devel
     Default --pass is generated and printed once. Save it.

     devel host, two products on ecom:

       andromeda -n site-add mysite www --host www.devel --name "WWW devel"
       andromeda site-add mysite www --host www.devel --name "WWW devel"
       andromeda site-add mysite shop  --host shop.devel  --name "Shop devel"

     Browse http://www.devel and http://shop.devel
     (dnsmasq on the devel host and --localhost maps *.devel).

5. Worked example — devel host ecom from zero
--------------------------------------------------------------------

  # 1 host
  ./andromeda-install.sh -n -m devel
  ./andromeda-install.sh -m devel

  bee --root=/srv/platforms/mysite/web --site=shop  status

8. After the site exists — Bee, not Andromeda
--------------------------------------------------------------------

Andromeda builds the box and the first install.
Everything else is Bee with --site.

  bee --root=/srv/platforms/mysite/web --site=www status
  bee --root=/srv/platforms/mysite/web --site=www cc all
  bee --root=/srv/platforms/mysite/web --site=www updb
  bee --root=/srv/platforms/mysite/web --site=www config-export
  bee --root=/srv/platforms/mysite/web --site=shop  config-import
  bee --root=/srv/platforms/mysite/web --site=www db-export /tmp/thq.sql

A Bee command without --site on a multisite tree may pick
the wrong product.

Promote code: commit on devel, merge devel → test → live in Gitea,
pull the matching checkout on the VPS, then updb + config-import
per product. That workflow is in ecom-multisite-tutorial.txt.

11. Ops: backup, check, promote, journal, cron
--------------------------------------------------------------------

  # smoke test after an upgrade
  andromeda -n site-check mysite www --host www.devel
  andromeda site-check mysite www --host www.devel

  # one product
  andromeda -n site-backup mysite www
  andromeda site-backup mysite www
  andromeda site-restore mysite www
  andromeda site-restore --from /srv/andromeda/backups/mysite/www/devel/20260916-210000 mysite www

  # copy a product (new hostname)
  andromeda site-clone mysite www mysite www-copy --host www-copy.devel

  # every product on this box (also nightly via /etc/cron.d/andromeda)
  andromeda backup-all

  # VPS only — devel host role=devel will refuse
  andromeda -n promote mysite --to test
  andromeda promote mysite --to test
  andromeda promote mysite --to live

  # same as promote's second half, if git is already current
  andromeda platform-upgrade mysite-test

  # task journal
  andromeda log 20
  andromeda last

  # maintenance
  andromeda site-disable mysite www
  andromeda site-enable mysite www

  # Bee cron by hand (installer already schedules cron-all)
  andromeda -n cron-all

DB passwords live in /srv/andromeda/state/secrets/<platform>/<product>
mode 0640 deploy:www-data — site-add does not print them.

site-delete is not built. A failed site-check does not auto-restore.

Exit status:
  0  succeeded (doctor READY, site-check OK)
  1  understood the command, could not finish
     missing platform/product, Bee/git/MariaDB failed,
     promote dirty tree or non-ff branch, site-check failed,
     mutate lock held, doctor NOT READY
  2  usage
     unknown flag, missing args, promote --to devel,
     or promote on a host whose role is devel

  echo $?
  andromeda last          # mutating commands also log rc=

12. Common mistakes
--------------------------------------------------------------------

  sudo andromeda
    Don't. The wrapper sudoes the few root steps.

  One working copy for devel + test + live
    Don't. Separate checkouts: ecom, mysite-test, mysite-live.

  Bee without --site
    Wrong product, or Bee refuses.

  Putting $database in settings.php
    That file is committed. DSN belongs in settings.local.php.

  Overwriting settings.local.php
    site-add will not. If the DSN is wrong, edit the file.

  CSF -F before WireGuard works
    Stay on TESTING=1 until you can SSH via 10.8.0.1.

  dnsmasq on the VPS
    The installer will not install it for -m test or -m live.
    Use public DNS.

  andromeda promote on the devel host
    Role devel refuses. Push from the devel host, promote on the VPS.
